# Premium car detailing website + booking system

Next.js 16 · React 19.3 · Tailwind 4 · GSAP + Lenis · React Three Fiber · PostgreSQL + Drizzle · Stripe · Resend · Twilio · Better Auth.

- Marketing site with a 3D scroll hero, page transitions, before/after gallery, SEO and local city pages.
- An 8-step booking wizard: service, vehicle, location, date/time hold, contact, review and deposit, confirmation. There is also a custom-quote path.
- Double-booking is impossible at the database level (Postgres exclusion constraint).
- Customer manage links for rescheduling and cancelling, with automatic refunds per policy.
- Admin dashboard: calendar with drag to reschedule, bookings, leads, quotes, catalog, schedule, service area, settings, content, promo codes, metrics and CSV export.

Design and decisions: [`docs/PLAN.md`](docs/PLAN.md). Test results: [`docs/VERIFICATION.md`](docs/VERIFICATION.md) (generated by `pnpm verify:report`).

## Quick start (local)

Requirements: Node.js 24+, pnpm 12 (`npm i -g pnpm@12`). No Docker needed.

> **Windows:** keep the project in a short path (e.g. `C:\dev\detailing-site`). Several native tools (esbuild, Postgres, Next SWC) fail beyond the 260-character path limit.

```bash
pnpm install
pnpm dev:db            # starts a local Postgres 18 (data in .data/pg), runs migrations, prints DATABASE_URL
cp .env.example .env   # paste the printed DATABASE_URL; leave the rest blank for local dev
pnpm db:seed           # sample catalog, hours, zones and clearly-labelled sample content
pnpm admin:create --email you@example.com --name "Your Name"   # prints a temporary password
pnpm dev               # http://localhost:3000  ·  admin at /admin
```

With keys left blank, local development uses safe fallbacks:

- payments are skipped ("pay at appointment"), or set `PAYMENTS_DRIVER=fake` for a test payment panel
- email and SMS are logged instead of sent
- the bot check uses Cloudflare's test mode
- photo uploads go to `.uploads/`

The owner account must turn on 2FA on first sign-in (set `ADMIN_2FA_OPTIONAL=1` to skip this locally).

## Environment variables

Every variable is listed with comments in [`.env.example`](.env.example). What happens when each one is missing is documented in `docs/PLAN.md §8`. A unit test fails if a variable used by the code is missing from `.env.example`.

## Database

| Command | What it does |
|---|---|
| `pnpm db:migrate` | Applies `db/migrations/*.sql` in order (advisory-locked; safe on concurrent deploys) |
| `pnpm db:seed` | Inserts anything missing; never overwrites admin edits |
| `pnpm db:reset` | **Dev only.** Wipes catalog, content and schedule tables, then re-seeds |

The schema lives in SQL (`db/migrations/0001_init.sql`) because the double-booking guarantee is a Postgres `EXCLUDE USING gist` constraint. `db/schema.ts` is the Drizzle mapping.

## Tests

| Command | Covers |
|---|---|
| `pnpm test` | Vitest unit + integration tests. Starts its own throwaway Postgres; includes real concurrent-booking tests |
| `pnpm e2e` | Playwright: builds, starts an isolated server (own DB, fake payments, captured messages, test clock) and runs booking scenarios 1–17 on desktop Chrome, mobile Safari (WebKit) and mobile Chrome, plus admin and smoke tests on Firefox, WebKit and Edge |
| `pnpm site-checks` | Crawl for broken links, axe accessibility on every page, SEO, security headers, reduced motion, WebGL-off fallback, tap targets, fonts |
| `pnpm check:bundle` | Initial-JS budget (≤ 170 KB gzip) for the mobile home page, against a running server |
| `pnpm lhci` | Lighthouse CI budgets (mobile; `LHCI_PRESET=desktop` for desktop) |
| `pnpm e2e:stripe` | Optional: real Stripe test-mode payments. Needs test keys and `stripe listen --forward-to localhost:3100/api/stripe/webhook` |
| `pnpm verify:report` | Writes `docs/VERIFICATION.md` from the latest results |

First run: `pnpm exec playwright install chromium webkit firefox`.

## Deploying

### Vercel (recommended)

1. Create a Postgres database (Neon via the Vercel Marketplace works well; PG 17+, `btree_gist` and `citext` are available).
2. Import the repo in Vercel and add the environment variables from `.env.example` (Production).
3. `vercel.json` runs `pnpm db:migrate` before each build and schedules `/api/cron/tick` every 5 minutes.
   - **This needs a Vercel Pro plan.** Hobby only allows daily cron.
   - Bookings stay correct without cron, but reminders would be late.
4. Stripe → Developers → Webhooks: add `https://YOUR-DOMAIN/api/stripe/webhook` with these events, then copy the signing secret into `STRIPE_WEBHOOK_SECRET`:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.async_payment_failed`
   - `checkout.session.expired`
   - `refund.updated`
5. Run `pnpm admin:create` once against the production `DATABASE_URL`.
6. Run `pnpm launch-check` with production env until it passes.

### Docker (DigitalOcean, AWS, any VPS)

```bash
cp .env.example .env              # production values + POSTGRES_PASSWORD
docker compose up -d db
docker compose run --rm migrate
docker compose up -d app scheduler
```

- `scheduler` calls the cron endpoint every 5 minutes.
- Put a TLS reverse proxy (Caddy, Traefik or a load balancer) in front of port 3000.
- The image healthcheck uses `/api/health`.
- Back up the `pgdata` volume, or use a managed Postgres with point-in-time recovery.

## Admin walkthrough (for the business owner)

Sign in at **/admin**. The first sign-in asks you to set up two-factor authentication with an authenticator app.

- **Overview:**
  - Appointments, booked value and collected payments for 7/30/90 days.
  - The booking funnel shows how many visitors reached each step.
  - Lead sources.
  - A yellow "Needs attention" box appears if messages failed, a payment webhook failed, or scheduled jobs stopped.
- **Calendar:** day view (one column per crew/bay) or week view. Drag a booking to a new time, or use its **Move** button. The system refuses times that would double-book.
- **Bookings:**
  - Search and filter, then open a booking to see the job, price breakdown, customer, history and every message sent.
  - Buttons: **Start job**, **Mark completed** (sends the review request), **Mark no-show** (keeps the deposit), **Record payment** (balance taken in person), **Cancel booking** (owner only; refunds per policy, with an option to waive the fee).
  - Internal notes are never shown to customers.
- **Leads:** contact-form messages, quote requests and unfinished bookings (only when the customer agreed to be contacted). Set a status and keep notes.
- **Quotes:**
  - Open a request to see the description and photos, enter a price, hours of work and an optional deposit, then **Send quote**. The customer gets a link to accept and pick a time.
  - For jobs longer than one day, add time blocks for the extra days in **Schedule** after they book.
- **Customers:** contact details, SMS consent record, full history. **Anonymize** handles privacy requests.
- **Catalog:**
  - Services, add-ons and packages, with base price and duration.
  - Optional per-size overrides (leave blank to use the size multiplier).
  - Vehicle size multipliers.
  - Rules: "requires" adds a prerequisite automatically with your explanation; "can't combine with" blocks a combination.
  - Condition surcharges.
- **Schedule:** opening hours, closed dates, crews/bays (how many jobs run at once) and time blocks (time off, equipment down).
- **Service area:** zones by ZIP code and/or radius, each with a travel fee and travel minutes. City landing pages are only worth publishing with genuinely local content.
- **Settings** (owner): deposit, cancellation window and late fee, reschedule limits, minimum notice, booking horizon, slot interval, buffers, hold length, tax and price rounding.
- **Promo codes:** percent or dollar discounts with optional limits, end date, and a "first booking only" option.
- **Content:** reviews (real ones only), before/after gallery and FAQs.
- **Export** (owner): CSV files for bookings, customers, leads and payments.

## Operations checklist

- **Email:** verify your domain in Resend and add the SPF, DKIM and DMARC records, or emails will land in spam.
- **SMS (US):**
  - Register a toll-free number (verification takes about 3–5 business days and needs a business registration number) or complete A2P 10DLC (about 10–15 days).
  - Enable Advanced Opt-Out in the Messaging Service.
  - Point inbound messages to `/api/twilio/inbound`.
- **Apple Pay / Google Pay:** verify your domain in the Stripe dashboard (Settings → Payment methods).
- **Monitoring:** watch `/api/health` with an uptime monitor.
- **Backups:** enable point-in-time recovery on your Postgres.
- **Upgrades:** pnpm only installs releases at least 7 days old (`pnpm-workspace.yaml`). Drizzle ORM 1.0 is in RC; the project pins 0.45 and the upgrade will need its migration guide.
